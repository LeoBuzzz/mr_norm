# Отчёт по этапу 1 парсера вопросов

Дата offline-приёмки: 2026-10-07.
План: `PLAN_QUESTION_PARSER.md`.
Спецификация: `SPEC_QUESTION_PARSER_STAGE1.md`.

## Результат

Вердикт независимой приёмки GPT-6 Astra medium: **accept_offline**.

Реализован dry-run разбор вопроса без вызова поисковых скиллов:

- лёгкая LLM классифицирует простой/сложный вопрос;
- отдельный лёгкий или тяжёлый parser возвращает единый план;
- код проверяет задачи, документы, пункты, semantic elements, constraints,
  evidence, зависимости, уточнения и статусы;
- используются существующие каталог, словарь сокращений и снимок диалога;
- поддержаны независимые вызовы `exact_point`, `corpus_point_search`,
  `find_all`; неподдержанные и зависимые действия получают `deferred`;
- неоднозначность возвращает конкретное уточнение;
- открытые и закрытые pending clarification проверяются без угадывания.

Скиллы, Qdrant, production-планировщик и бот не изменялись и не вызывались.

## Распределение проверки

- Реализация: GPT-6 Luna medium.
- Независимые тесты: GPT-5.5 Sol medium.
- Критика: GPT-5.6 Sol medium.
- Offline-приёмка: GPT-6 Astra medium.

Исправления проходили циклом implementation → tests → critique → acceptance.
Критические находки включали самозависимость задач, слабое смысловое сравнение,
несогласованные fixtures, утечку metamorphic-пары в holdout, незаземлённые
pending-условия, неоднозначные документы и номера пунктов, а также смешение
номеров пунктов с числами и единицами измерения.

## Ограничения

`accept_offline` подтверждает контракт, валидацию, fixtures и оркестрацию с
fake adapters. Он не подтверждает качество реальных LLM, задержку или стоимость.
Runtime provider и точные light/heavy модели не выбраны; live gate не запускался.

Production `DialogContext` пока не даёт постоянных стабильных ID подтверждённых
условий; полная интеграция памяти относится к следующему этапу. Синтетические
cases преобладают над реальными, поэтому live pilot остаётся обязательным перед
решением о дальнейшем подключении. Отдельный adversarial live-набор для prompt
injection желателен до executor, но не был blocker offline-этапа.
