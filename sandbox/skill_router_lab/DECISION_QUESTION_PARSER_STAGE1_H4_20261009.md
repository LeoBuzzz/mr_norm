# H4 — вывод Astra по завершённому H3 r10

2026-10-09. Verdict: **spec_ready**. Код и frozen artifacts не менялись.
Sampling не разрешён; следующий шаг — ограниченная реализация Luna medium.

Главная причина четырёх лишних уточнений обнаружена непосредственно в
router_prompts_v3_h3.py: parser обязан считать flat strings отдельными смыслами
и не объединять синонимы. Это противоречит проверяемому поведению для обычной
аббревиатуры и её однозначной расшифровки. `_candidate_sets` делает каждый
surface самостоятельным legacy ID; это wire representation, а не доказательство
семантической неоднозначности. Модель следует неудачной инструкции.

V01/V03/V06/U03 уже имеют верную task semantics. Их plan failures вызваны
лишним clarification/status, у V01/V06 ещё ошибочным complex. Одно согласованное
правило candidate semantics в parser/classifier правдоподобно восстанавливает
четыре случая до 17/20. Минимальный эксперимент не требует нового словаря,
нормализатора, schema или изменения scorer. Эквивалентность по числу кандидатов,
позиции в списке или одним инициалам запрещена; отсутствующее знание не выдумывать.

D03 — отдельный classifier-only сбой: scope-changing continuation ошибочно
simple, хотя parser правильно сохранил dialog continue, тему и документ.
Универсальное «вся история = complex» сломало бы простой point continuation.
Поэтому этот дефект явно оставлен вне H4.

A02/A03 действительно неоднозначны. Field, subject и все options правильны;
план не проходит из-за retained search task со scope=corpus вместо unresolved.
Это отдельная проблема task representation, которую нельзя маскировать новым
scorer или уничтожением ambiguity. A03 с разными expansions не объединять,
A02 с двумя doc IDs не объединять. Их текущие plan failures допустимы только
для промежуточного useful-эксперимента, а не для full acceptance.

U03 сохраняет operation define и unsupported_intent; устранение искусственной
ambiguity должно дать deferred, не готовый поиск или вызов definition skill.

Новая нормативная секция H4 добавлена в SPEC_QUESTION_PARSER_STAGE1.md с
сохранением истории H3. Разрешены только prompts, минимальное version wiring
существующего lifecycle и focused tests. Прогноз 17/20 не является результатом.
Проверка включает сохранение всех 13 r10 passes, настоящих ambiguity, прежних
critical gates и исторического replay. <=1 лишнее уточнение требует устранения
минимум трёх из четырёх искусственных уточнений. Строгий gate не ослаблен;
holdout закрыт. Роли прежние; недельный резерв обновлён пользователем до 2%.
