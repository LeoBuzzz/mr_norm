## Предложения по улучшению пайплайна

- **Prefetch ГОСТ:** не запускать для вопросов с явным `point_number` в формулировке и для `question_type != definition`; ограничить число GOST-сниппетов в merge (сейчас вытесняют top-N у case_008, case_016).
- **Point lookup:** при распознанном `п. N` / `подпункт` в вопросе — приоритет tool `point` + фильтр `doc_id`, если документ назван в тексте.
- **Планировщик:** для chunk-grounded вопросов с явным пунктом/документом в формулировке — детерминированный резолвер doc_id до LLM, без отказа при score 0.55.
- **Final answer:** запрет «информация отсутствует», если `resolved_doc_name` совпадает с документом из вопроса — повторный payload/point retry.
- **Неоднозначность:** не трактовать широкий hybrid как ошибку для comparison/wide_overview; снижать severity warning, если prefetch ГОСТ или несколько релевантных актов ожидаемы.
- **Регрессия:** периодически `--phase eval` на фиксированном `corpus_50.json` после изменений planner/retrieval.
- **Промпты Polza:** при score ≤ 5 чаще всего расходятся эталон (узкий фрагмент) и ответ (обобщение) — усилить final_answer правило «не расширять beyond evidence top-N».
